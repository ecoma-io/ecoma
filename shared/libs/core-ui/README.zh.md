# core-ui — Alloy

Alloy 是 Ecoma 以 `@ecoma-io/ui` 形式发布的设计系统：一套 Vue 3 + Tailwind
基础组件（primitive）、组合块（block）与设计令牌（token），目的是被所有
产品界面**复用**，而不是各自重新实现。它的形式语言是两种力量的结合——
Human（钢）× Agent（铜)——只在两者交汇处才出现渐变焊缝；整体基调是浅色
优先、企业级。

<!-- readme:why -->

## 为什么存在

Ecoma 是一个人类与智能体并肩工作的工作区，对人类一侧而言，这首先意味着
界面——而这些界面会跨越本仓库未来会有的每一个产品边界（独立应用、
workspace 外壳，或某个产品在其之上的自有组合）。如果每个产品都各自重新
实现同一个按钮、对话框或骨架屏，每份实现都会在间距、动效与无障碍性上按
自己的节奏产生偏差。Alloy 的存在就是为了让通用的可用性单元——一个基础
组件、一个令牌、一个动效模式——只被构建一次并在各处复用，双向各有一条
硬性规则：产品在动手重做之前必须先复用；而在某个产品内部草拟出的任何
通用组件，都应当"毕业"（graduate）到这里，而不是留作本地分支。这不是
"看起来足够通用"这种模糊判断，而是一份具体的组件清单，被多个互不相关的
产品以同样的方式依赖。

<!-- readme:consumers -->

## 谁在使用它

工作区中任何面向界面的应用或产品自有 UI 库，通过 `@ecoma-io/ui` 引入。
目前仓库内还没有真正的消费者——当前只存在 `shared/`，尚未有任何产品域
——因此这个库目前作为未来产品界面的基础层被保留。与此同时，`design-system`
应用的 Storybook（`pnpm nx run design-system:serve`）就是其设计文档的实际消费者：每
个基础组件的 `.mdx` 页面，以及 `docs/design/*` 下共享的规范页面
（Motion、Color、Elevation、Typography、Iconography、Logo、Signature、
Principles）都在其中渲染。

<!-- readme:ecosystem -->

## 它在生态中的位置

Alloy 是两层 UI 体系中的第一层：本库拥有所有_通用_的可用性单元（基础组
件、组合块、令牌、动效），而每个产品自有的 UI 库（第二层）只拥有该产品
在其之上的组合逻辑。正是这种划分,让一个产品在上线某个界面时,无需重新
决定一个按钮或一个确认对话框该长什么样。这里的每个基础组件都由五个共同
存放的产物组成（组件本体、测试、demo、stories、设计文档 `.mdx`），而
`docs/design/*` 下的设计页面则是共享规范——所有基础组件都依赖的词汇表
（令牌、关键帧、动效模式、图标集）。

<!-- readme:boundary -->

## 它刻意不做的事

它对任何产品的领域一无所知——没有视频时间线，没有浏览器 profile 列表，
没有流程编辑器。它不包含路由、不做数据获取、不含业务逻辑；这里的基础组
件只接收 props 并发出事件,仅此而已。产品特定的组合逻辑属于各产品自有的
UI 库（第二层），永远不属于这里——反过来也成立：一旦第二个产品需要同一
个通用组件，它就应当"毕业"到本库，而不是在下游被重复实现。

<!-- readme:status -->

## 当前状态

已构建完成，并通过 `design-system` 的 Storybook 得到验证，仓库内尚无实际消费者——
目前作为未来产品界面的基础层保留。相关机制——每个基础组件的五个共存产
物、consume-first / graduate-upstream 规则、令牌的唯一可信来源，以及
Tailwind v4 的若干坑——记录在 [`./CLAUDE.md`](./CLAUDE.md) 中。
