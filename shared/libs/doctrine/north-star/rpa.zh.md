# Ecoma RPA — North Star

## 终态

**Ecoma RPA 是 computer-use 世代的环境交互自动化引擎：每一个动作都是带身份、带
reversibility 分级、带证据的实体；每一次会话都是 durable、可重放、可被人中途接管的；确
定性脚本与视觉 agent 是同一条成本–耐久轴的两端，并具备双向自愈——既可独立使用，也可通
过恰好两个标准接口成为 [Ecoma Platform](platform.md) 的劳动来源。**

它所特化的机制原则与 invariant 的 canonical 出处在
[Platform North Star](platform.md)，此处不再重述。

## 问题所在，以及定位

基于 selector 的自动化是一个维护黑洞：界面一变它就碎。computer-use agent 在界面变更下
存活得好得多，但没人敢让它真的跑起来——没有 reversibility，没有标准动作日志，不区分看
与写，而且密钥会落进模型的上下文里。

这两者之间的空白就是整个产品：**一个每一个动作都可问责的自动化运行时。** 这在本系统里
并不是一个新想法；它就是 Ecoma 设计的其余部分被压到执行层。

## 五条机制原则

它们特化那四条 canonical 原则，而不是取代它们：

1. **绝对对称。** 人的动作（接管、演示）与机器的动作（脚本、agent）进入**同一份动作日
   志**，用同一套 schema，只在 actor identity 上不同。两份日志意味着两个真相，而真正
   要紧的问题——这次会话里究竟发生了什么——就不再有唯一答案。
2. **带 lineage 的稳定身份**，适用于一切会积累的东西：动作定义、脚本、driver、应用画
   像。被自愈修补过的脚本是一个从其父继承而来的新版本。
3. **引擎强制存在，template 强制取值**——外加本 domain 特有的一条保守规则：**未声明的
   reversibility 一律按不可逆处理。** 对沉默的安全解读，是唯一一种以安全方式失败的解
   读。
4. **复杂度是用户的选择。** 一个裸脚本无需声明任何东西就能跑；guard、脱敏、scope 与确
   认全都通过 cascade 成为 opt-in。
5. **Integration first。** RPA _始终_ 发出 Session effect 并讲 Filler 接口，**包括独
   立运行时**——那时由一个极简的本地 consumer 顶替 Platform。不存在第二条执行路径，因
   此两种模式无从漂移。

## 部署拓扑：Node

一个 **Node** 是安装在某台机器上的 RPA 应用——员工机器是 _attended_，服务器是
_unattended_，两者跑同一个二进制。node 是**宿主，不是 Filler**：各个 filler（一个脚本
版本、一份 agent 配置）_经由_ node 注册。一个 node 托管多个 filler，一个 filler 可以在
多个 node 上运行。

**Placement。** node 声明自己有什么：已安装的应用、可用的持久 profile、网络区域、容
量、是否有人在场，以及它的 engine 版本与 protocol 版本。指派按一条链解析——role，然后
filler 池，然后一个够格的 node，而版本正是够格条件之一。

**Pull，只出不进。** node 从服务端领取任务。Platform 从不把远程控制指令推进 node。会话
在本地运行，Session effect 反向流回。传输方式是细节；必需的机制是 outbound-only 加上
**一条带可恢复游标的流**。断网时会话在本地依旧 durable，日志缓冲，重连后从原偏移继续
——条目是内容寻址的，因此至少一次投递会自行去重。若 node 死掉，会话以中断收场，且其状
态有证据可以支撑。

**一次领取是一份带心跳的 lease**，而它的过期刻意不等于一次重跑。一旦日志显示动作已经发
生——尤其是越过了 commit point——悄悄改派工作就等于在一个真实系统上重复一次 effect。它
转而成为一次中断加上已声明的失败路径。会话**钉在它的 node 上**，不迁移，因为它的状态是
本地的。

**注册是强制的。** node 拥有加密身份，且由管理员显式批准。携带某个 credential scope 的
任务只路由到显式获授该 scope 的 node，而 vault 只在 driver 层、按会话限定范围、向已注
册的 node 身份签发短时效密钥。有计划的下线是一次 **graceful drain**：node 停止领取，运
行中的会话自然结束或按 lease 改派，然后吊销密钥——每一步都是一个 event。这与被攻陷 node
的紧急吊销是不同的流程，后者立即切断。

**接管有通道，但绝无常驻权限。** 不存在任何环境性的远程控制能力。查看或控制通道**按会
话打开、由 node 主动发起、方向向外**，前提是一次 assistance request 被接受且 node 自身
的策略允许。人的每一次输入都经过 driver，成为带 actor 的 Action，进入同一份日志。在
attended node 上，接管路由到就坐在那台机器前的人——那个人同样是一个 Filler。

**Attended 是 consent-first**（空闲时运行、用户触发、或在独立的虚拟桌面中——一条策略
cascade）。**Unattended 是 isolation-first**（沙箱或虚拟机）。

**本地 attended UI 不是第三个接口。** node 运行时是一个同时跑两种模式的无头二进制；
attended 机器额外安装一层本地 UI，通过一条以 node 身份认证的机内通道与运行时对话。三条
硬边界使它无法成为系统的一个接口：

1. 机内通道只承载**本地会话控制**——打开、关闭、暂停、接管。它不承载 effect 流，也不承
   载劳动语义。
2. **attended UI 的每一次劳动行为——批准、裁决、领取、释放——都直达引擎 API**，与任何其
   他客户端一样。UI 没有自己的私有写入路径。
3. attended UI **不存任何帧**。抵达日志的永远是一份已脱敏的 Scene。

试金石很直接：把机内通道关掉，node 运行时照跑——它只是失去了 UI——而没有任何写入路径丢
失，因为它们本就没有一条走过那条通道。

**node 更新有退路。** 经由 Hub 更新 node 是一个显式动作，而**退回上一个 digest 同样显
式、同样是一个 event**，在已声明的偏斜窗口内有效。没有退路，"更新"就成了对全系统安全最
敏感组件的一次单向操作。

**证据以哈希即时上行、blob 惰性上传**，因此日志完整性是即时的，而带宽不成为瓶颈。node
通过 Hub 自身更新并校验签名，且**在任何默认配置下都绝不自动更新**。

## 每个 RPA 概念在集成后成为什么

| 在 RPA 中                                                    | 接入 Platform 后成为                                                                                                                           |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Session                                                      | 某个 Task 的 Session effect                                                                                                                    |
| 人工接管                                                     | 一次 assistance request——一次 escalation，其处理者本身也是一个 Filler                                                                          |
| 一个被治愈的脚本版本                                         | 一个带 lineage 的新 Filler identity，经过各信任层级                                                                                            |
| 一次自愈确认                                                 | 一道 Gate，其 criteria 由 reversibility 推导                                                                                                   |
| 动作日志加证据                                               | 某个 Artifact 的 provenance                                                                                                                    |
| 一份应用画像                                                 | Hub 上的一个 block 类型；装进租户后即成为 cascade 默认值的一个来源                                                                             |
| 界面漂移信号                                                 | escalation 与 intelligence 的输入——执行层的一种流程气味                                                                                        |
| 一个只读会话 scope                                           | 当 agent 自行创建 RPA 任务时，spawn policy 上的一条护栏                                                                                        |
| **一个 automation**（脚本版本加自愈策略，或一份 agent 配置） | **就是那个已注册的 Filler。** 在脚本、agent 与人之间移交某一个动作，是 filler _内部_ 的行为，记录为 sub-actor；calibration 跟随已注册的 filler |
| 学习信号                                                     | 由 Session effect 加同一条流中的 `proposal` 条目派生——**不是第三个接口**——最终落成 Judgment、escalation，或按租户的 calibration                |

## 确定性与推理，在同一条轴上

同一条轴，按**每个动作**而不是按产品来拨：

| 方面       | 确定性             | 推理                |
| ---------- | ------------------ | ------------------- |
| 执行器     | 脚本，结构层       | 视觉 agent，语义层  |
| 从哪里起步 | 录制一次演示       | 从 agent 蒸馏       |
| 解析目标   | 结构锚点           | 语义意图            |
| 校验       | 前置条件断言       | 对账与自愈          |
| 移交       | 失败时脚本 → agent | 稳定后 agent → 脚本 |

## 唯一一个学习内核，而 RPA 是它的信号生产者

**RPA 没有自己的学习内核。** 唯一的内核是 Platform 的 intelligence 层。学习信号不是第
三条通道：大部分派生自动作日志本身，也就是 Session effect，而各类_提议_——修补应用画
像、蒸馏成脚本、更改模型路由——是同一条流中 `proposal` 类别的条目，由 Platform 物化成
Task。独立运行时，一个极简的本地 consumer 只做确定性统计：计数、阈值，以及在**它自己的
脚本内部**按同样的审批规则提升某个锚点。刻意不存在第二个大脑可以偏离第一个。

每一条提议都**经由一次评审**落地，绝不通过修改运行时。信号属于租户；社区目录只在 opt-in
且经过评审时才接收它们。

## 试金石

1. 同一个 automation 能否在不改动其定义的前提下，既用脚本运行**又**用视觉 agent 运行？
2. 当脚本因界面变更而碎掉时，agent 是否接管并产出一个带 lineage 的补丁版本，而无需人工
   编辑？
3. 能否从日志与证据重放任意一次会话——谁或什么、在何时、做了什么、屏幕是什么样子？
4. 当人在会话中途接管时，他们的动作是否与机器的动作落在同一份日志里？
5. 密钥是否曾出现在日志中、出现在交给模型的截图里，或出现在某个 agent 的上下文中？
6. 独立运行与集成运行是否是**同一个二进制、同一条 effect 路径**？
7. 若 node 在会话中途断网，会话是否在本地继续，并从游标恢复且不丢不重？
8. 未注册的 node 能否领取任务或获得密钥——即便它声明了完美的 placement 属性？
9. 是否存在通往 node 的常驻控制通道，还是接管只按会话打开、由 node 发起、每次输入都成
   为带 actor 的 Action？
10. 关掉 attended UI 的机内通道：运行时是否照旧运行，是否有任何写入路径丢失？

## Non-goals

- **不做多步骤、多角色、带检查点的编排。** 那是 Platform 的活。
- **不是集成平台。** 有 API 的地方就调 API——那是 Platform 侧的一个 rule filler。RPA 用
  于**没有** API 的地方。
- **不自建视觉模型。** 模型经由 adapter 到来，采用开放分类。
- **密钥不存放于 vault 之外**，且尽管同处一个仓库，**也没有与 Platform 的私有集成路
  径**。
- **不做不可检测性工程。** 解决呈现给一个已授权会话的访问挑战——租户持有凭证的登录
  前的一个 CAPTCHA——是一个普通的 Action，像任何其他 Action 一样带着它的 actor 记入
  日志，而这正是"用于没有 API 的地方"的含义。引擎**不**编写的是与之相反的能力，其唯
  一功能是让目标方把机器误判为人：指纹伪造、住宅代理轮换、为击败检测器而调校的时序
  模仿。理由是该领域自身的立场——每个动作都可问责，而这种问责是**端到端**的：驱动一
  条已授权的人类路径会让目标方自己的日志保持真实，而规避恰恰是为了让那份日志说谎。
  两者是不同的行为，界线画在会话的权限范围（Sandbox & Credential §4）。需要不可检测
  性能力的租户以 opt-in 的 `code` 类 driver 安装它，并自行承担服务条款与法律风险；引
  擎既不发布也不推广它。

## 分发

- 本 domain 住在自己的 area 中。授权遵循 [Platform North Star](platform.md) 中的
  canonical 分类规则——动作词汇表、driver 接口与应用画像 schema 是第三方要接入的东西；
  内核与 node 运行时是拿来运行的东西。本文档不重述那条规则，因此它不存在第二个来源。
- 应用画像、宏、脚本与 driver 以 **block 形式经由 [Hub](hub.md)** 分发——RPA 通过客户
  端接口直接与 Hub 通话，独立运行时亦然，而不绕经 Platform。driver 是 **code** 类
  artifact，属于一个独立的信任类别：它要求发布者已 verified，并需管理员显式 opt-in。
- 独立运行意味着一个命令行、一套 SDK 与自托管。它是采用的楔子：为自动化而来，为
  Platform 而留。

## 失效模式

| 失效                  | 由什么发现                | 如何恢复                                                                              |
| --------------------- | ------------------------- | ------------------------------------------------------------------------------------- |
| node 在会话中途断网   | 心跳与 lease 过期         | 会话在本地保持 durable 并从游标恢复；若 node 彻底死掉，则以中断收场，其状态有证据支撑 |
| node 被攻陷           | 注册身份与密钥吊销        | 一切领取与一切密钥请求立即被拒绝                                                      |
| node 上证据缓冲区写满 | 哈希已上行，blob 是惰性的 | 一条容量告警；日志完整性不受影响，因为哈希已经记录在案                                |
