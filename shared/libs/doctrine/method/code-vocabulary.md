# Code vocabulary — namespace ownership and citation

Every family of designation code in this project has exactly one owning document. This page records **who owns which prefix, what shape it takes, how it must be cited, and what — if anything — enforces it.** It records nothing else.

**It is not a registry, and it holds no code's meaning.** To learn what a code says, open its owner: a second copy of the values would be stale from its second edit, and it would be the copy a reader trusted. What cannot be derived from any owner is the _citation form_, and that is the only content here.

## Three rules this page holds

**The one-owner-per-prefix rule.** A code family is defined in exactly one document. A second document that defines the same prefix has forked the namespace, and that is a finding rather than a convenience.

**The select-one-owner rule.** A citation must select exactly one owner. Being greppable is necessary and not sufficient: where a prefix is shared, a bare code resolves to two documents and the reader cannot tell which was meant. The citation therefore carries the owner's name, or the section anchor that selects one — in full on first use inside a document, short afterwards.

**The append-only-never-reused rule.** A retired number stays vacant; a replaced entry keeps its number and changes its text. Renumbering is forbidden, because every citation written before a renumber then points at something else _and reads as correct_. Each owner is where that discipline binds; the Format law column below records only the shape a citation must carry — never which numbers are vacant, which stays the owner's to keep.

## Collisions this project keeps

Renaming either side of a collision would break every citation written before the rename, which is the failure this page exists to prevent. Each is therefore **accepted**, and the cost is paid by the select-one-owner rule instead.

- **`R<n>` and `<Track>.<seq>` on track R.** The review rubric's law numbers and the roadmap's track-R item ids render as the same token once the dot is dropped. Consequence: the owner name is mandatory on this prefix, on both sides.
- **Group `F` criteria and a review run's finding ordinals.** They share a letter, and the tree's gate separates them by _shape_: the two-digit form is refused here, the one-digit form is this corpus's own. Consequence, recorded so it is not discovered by a red build: **a group-F criterion cannot grow to a two-digit ordinal** without moving that gate first.
- **`Rule <n>` and `rule #<n>`.** Two unrelated families separated only by a capital and a hash. Consequence: both citation forms are written in full — `Rule 13`, and `roadmap §1b rule #7`.
- **Group `P` criteria and `P<group>.<n>`.** Consequence: the proposal rubric's codes always carry their owner's name.

## What this page does not do

- **It does not renumber anything.** Every family above is append-only and frozen in that sense already.
- **It holds no values.** No list of what a code says, in any row.
- **It does not govern product vocabulary** — the primitives, the event taxonomy, a specification's section numbers. Those are not designation codes.
- **It adds no gate.** Each row's rung is one that already exists. Where a row says review-only, no machine reads it, and a green run says nothing about it.
- **It names ephemeral thread codes so they can be excluded, never so they can be cited.**
- **It reaches only the published tree.** What a withheld document numbers internally is that document's own business.
