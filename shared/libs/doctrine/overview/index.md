## System shape

```
3 vertical domains: Platform | RPA | Hub (one North Star each)
2 horizontal layers: EE (license layer, extension points) | Cloud (operating form + internal control plane)
Boundaries: Platform↔RPA = 2 runtime interfaces (Filler + Session effect)
 Everyone↔Hub = resolve/pull/verify (never touches runtime)
```

## Canonical glossary (L6 — one concept, one name)

Role (a position of labour) / Filler (the person·agent·rule·process filling a Role) · Task / Attempt · Checkpoint = {Gate (the stop), Judgment (a signed verdict), Criterion (a library criterion)} · Handoff / Contract / Artifact (CAS, immutable) / Envelope (a context projection) · Effect (reversible/compensable/irreversible) + serialization_key · Escalation (open taxonomy, terminal state mandatory) · Trigger / Channel / subject binding · Block (the unit of distribution; a Template is a curated block) · Collection / Chunk / Curator (Knowledge) · Memory entry / Subject / Party · DataTable (writable projection) / Lease (a uniqueness lock with a TTL) · Projection (any view of the Event Log) · Classification lattice / leakage gate · Calibration (about the worker) ≠ Memory (about the party served) · Node (an RPA host) / Session / Scene · Principal (user·agent·rule·node·external) / Tenant (a hard boundary with a lifecycle, §2b) / Workspace (a soft partition) · **CalKey / Cell** (the calibration key and cell, a projection) · **Estimator identity** (the method@version of an estimate) · **Reference backend ≠ installation default** (Postgres produces the canonical contract suite; what a user receives depends on the operating form — ADR-0002) · **Small stack** (SQLite + DuckDB + sqlite-vec, for the single-binary / single-container form) · **Work Item / Action Item** (Human Surface) · **`test_behavior`** (mock/dry_run/forbidden — contract behaviour under test) · **Rotate ≠ Shred** (rotating a key does not re-encrypt; destroying one erases permanently) · **App Profile** (per-application knowledge: a reversibility layer plus stable locators; a block type) · **Scene** (a three-layer environment snapshot, content-addressed, already masked) · **Evidence** (the scene hashes before and after an Action) · **Commit point** (the first irreversible action already executed — the edge of unwind) · **Sub-actor** (an actor _inside_ a filler: script⇄agent⇄human, a tool call — not a Task) · **Macro** (a named, versioned sequence of Actions) · **Vault** — two distinct senses: a _credential vault_ (operational secrets; RPA Sandbox §2 is the tier-1 subsystem's first consumer) ≠ a _pii_vault_backend_ (data-subject keys, an EE extension point — Tenant §8) · **Test run scope** (a run labelled `run_kind: test` inside the tenant itself — **not** a separate tenant; isolated by projection filter) · **`environment: production | test`** (a dimension of Filler identity — **not** a fifth trust tier; there are still exactly four) · **Mock filler** (a real Filler `mock:<name>@version` behind the real Filler interface) · **Fixture** (seed data with an id, a version and lineage) · **Assertion artifact** (a declared, versioned assertion measured against the log) · **Conformance suite** (the same harness mechanism, with an _implementation_ of a ◆G interface as its subject; changing the suite is breaking) · **`supports_dry_run`** (an adapter capability; unsupported ⇒ the `dry_run` contract resolves to `forbidden`) · **Workspace** (an **administrative/display** boundary inside a tenant — **NOT** a security boundary: same tenant DEK, same log namespace, deduplication permitted) · **Single-tenant self-host** (capped by a **product boundary** — the tenant-creation workflow ships only in `cloud/` — **not** by a license check) · **`<area>/enterprise/`** (Enterprise License, tag `license:ee`; `ee` may import `sul`, `sul` may never import `ee`) · **Release train `X.Y.Z`** (the version axis of the **workspace**, not of an app) · **Protocol version** (a monotonic integer, one per protocol) · **Rollback window** (outside it this is **no longer a rollback** but a restore plus replay) · **Support window** (the current major plus one before it; backup retention may not exceed it) · **The three deploy partitions** (`deploy/` ships · `cloud/` operates · `shared/tools/` develops) · **`run_kind: production | test`** (an entry label — canonical home Event Log §1/§3; every projection declares its position) · **Roll-forward replica** (a key replica that a `destroy` command can reach — the **only** valid replica kind for key material; point-in-time snapshots are forbidden) · **Clickstream ingest tier** (the second write path: a separate stream beside the Event Log, sampled by visitor, TTL-bound, never read by a labour decision) · **`visitor_ref`** (the pseudonymous visitor key on that tier — a subject key, shreddable, and **not** a new key tier) · **Enclosure** (the per-Attempt OS/VM boundary a `code` filler runs inside — the sandbox's unit of isolation, never a language-level restriction) · **Runtime image** (the versioned, distributable artifact an enclosure boots; a withdrawal is a `yank`, and a pinned package survives it as a named failure rather than a silent upgrade) · **Admission** (the decision to start a unit of work under a tenant ceiling — `reject`, `queue` or `degrade`, never silent) ≠ **termination** (what happens to work already running, which is `budget` and lease TTL, not quota).

**Unblocking state**: the **timing** and **trademark** conditions are lifted (reasoning under Publishing policy). What remains is **two editorial tasks**, with nothing for anyone to sign:

1. A **tone pass** over the ceiling (28 documents in the public layer).
2. A **status banner** reading _"design end-state, pre-implementation"_ on each file — now carrying the role the timing condition used to carry.

**Reasoning, overriding an earlier position — draft first, sign later (owner's call).** An earlier version of this item said _"do not grant SUL yet, wait for L9"_, and it merged two different things: **drafting the text** and **granting the right**. Only the second is irreversible. Keeping them merged had a visible cost: L3–L5 and L7 sat idle at 🟡 because everyone assumed they were waiting on counsel, when what counsel needs in order to work **is precisely those documents**. So the right order is the reverse — draft everything, let the tree carry a complete draft, then hand it to counsel once.

That moves the risk rather than removing it, and where it moves needs saying plainly: **the act of licensing is now the _merge_, not the _commit_**. While a pull request is unmerged nobody has received anything; once merged, whoever received under SUL keeps that right permanently. This is why L9 went from 🟡 to 🔴 with nothing new happening — it is no longer an item on a list, it is **the last blocker**.

**Reasoning — the licensor must be a documented human being (owner's call).** The first version named the owner as _"Ecoma"_, and `DEFINITIONS` defined the licensor circularly as _"the entity offering these terms"_. Three independent review branches stopped at exactly this point, so it is not a matter of style. The place it bites is not `LICENSE` but the `CLA`: a contributor grants a **perpetual, irrevocable** right to a name; when the time comes to enforce or to transfer the asset to a company, nothing connects that name to a legal person — **and it cannot be fixed after the grants have been received**.

The first fix replaced _"Ecoma"_ with an English name — **the same mistake one level down**, since that name appears on no document either. Final position: the licensor is a **legal name**, with an `also known as` clause connecting it to the name displayed in `package.json`, the commit history and the GitHub account. Two conclusions, both cheap and both missed the first time: **a pseudonym does not void a licence — it makes the right unprovable and non-transferable**, which is exactly what a CLA exists to solve; and **the displayed name is not the granting field** — commits, `package.json` and the GitHub handle stay as they are; only the place where rights are granted needs a real person.

**Two boundaries, now clear — do not conflate them again:**

- `LICENSE.docs` in `shared/libs/doctrine/` covers **every `.md` file in that directory and all subdirectories**; it does not cover source code. The boundary cuts by **file extension**, not by category: the earlier text said "prose", and "prose" is not a property a machine or a reader can judge — and this directory holds `src/` right beside the documents. Source code follows the classification rule at the top of this section; documents follow the root `LICENSE`.
- **Doctrine's CC BY-SA 4.0 does not change to SUL**, and that question is closed for good. Three reasons, heaviest first: CC BY-SA is **irrevocable** (§2(a)(1)), so what has been released cannot be recalled — a change would only produce a two-licence corpus; **SUL has no copyleft clause**, which discards the very ShareAlike mechanism the L2 reasoning cited as its reason; and SUL forbids **distribution for a fee**, which would block quoting the doctrine in any commercial context — the opposite of why it is published. Beyond that, SUL is a **software** licence: every noun in it is _the software_ or _source code files_, and applying it to prose is ambiguous from the first sentence.

**L3–L5 and L7–L9 are ONE counsel engagement** — do not split them; they share one set of questions. Drafting first only changes what counsel receives: a consistent tree instead of a list of requests.

**The draft went through one adversarial pass before arriving here**, and the three faults it found are worth recording because all three were **contradictions between two documents**, not faults inside one:

- The `doctrine` manifest declared `SEE LICENSE IN LICENSE`; npm resolves that string against the file at the **package** root, and that root file is the CC BY-SA text ⇒ the manifest declared the TypeScript source itself copyleft, **and the gate enforced exactly that wrong value**. The lesson: a derivation serving two axes with different semantics (a tag governs imports · a manifest governs files) fails on precisely the axis it was not designed for.
- The patent retaliation clause fired only on a claim that _"the software"_ infringes, while `DEFINITIONS` **excludes `cloud/` from "the software"** ⇒ suing the commercial control plane directly costs nothing. The shield covered the free part and left the revenue-generating part exposed.
- The `CLA` grants a patent licence **directly, irrevocably, to every recipient**, with no defensive termination ⇒ an attacker loses rights under `LICENSE` but keeps them under `CLA`. The internal document nullified the external one.

The litmus this yields, applied to every future licence edit: **read each pair of documents side by side, never one document at a time.** All three faults were green on every gate and correct when read in isolation.

**A second adversarial pass — and a more expensive lesson than the first.** The second pass did not look for new faults; it **tested whether the first pass's patches actually patched anything**. Result: 8 of 12 findings had merely _moved_, and **three patches created new BLOCKING faults of their own**. Worth recording because all three share one mechanism — locally correct, broken at the joint:

- The definition _"substantially the software itself"_ was kept while **its socket was replaced** by an (a)(b)(c) test using different wording ⇒ a sentence no clause consumes any more.
- A precedence sentence, _"Nothing in this paragraph permits what the next paragraph forbids"_, was added to the paragraph allowing commercial embedding, together with a `"Provide"` definition that includes provision over a network ⇒ **that paragraph self-destructs and permits nothing at all**.
- The patent hole was closed in `LICENSE` with a _"written claim"_ trigger and in `CLA` with an _"institutes litigation"_ trigger ⇒ the two documents fire at different moments, leaving exactly the pre-litigation window open — which is precisely the hole that CLA paragraph was written to fill, as its own rationale says.

Plus two faults nobody had caught: the outbound grant **never declares `perpetual`/`irrevocable`** while the CLA's inbound grant declares both (an asymmetry that breaks the self-host promise outright), and the doctrine carve-out's image clause binds **by reference rather than by path** — yet every image in the tree is a brand mark, so a single `![]()` puts the logo under an irrevocable CC BY-SA.

**The settled lesson: a patch is a new change, and must be attacked as a new change.** Once the first pass was patched, both the author and the gates treated it as closed; only a lens given the explicit job of _"check whether the patch actually patches"_ saw it.

## Gate ledger — the real state, in one place

**The gate rule** ([roadmap](../method/roadmap.md) §1b, rule #7): **a gate = a frozen document + a conformance test suite that runs independently**; the document alone is not enough, only the suite is an arbiter a machine can check. The roadmap's own litmus (§8) asks directly: does every ◆G gate have a runnable suite **before** the track behind it writes its first line of code — **"a gate with no suite is a paper gate."**

**The ledger that used to sit here is now derived.** `dev-cli conformance` reads the state of every gate off the tree — a freeze is a document declaring `status: frozen` and the gate it closes; a suite is a project declaring a `conformance` target and the gate it arbitrates — and prints one row per gate the roadmap defines. A hand-written table of the same thing was a second source of truth about a fact a command can read, and it is exactly the drift this file removed from its known-gaps section.

**The honest consequence, at the time of writing**: no document has ever been frozen, so **every gate ◆G0–◆G4 is still a paper gate** by the letter of rule #7 — how many suites exist alongside is exactly the fact the derived ledger reports, and this file deliberately does not restate it. That is not a fault to patch by freezing something: a real suite demands infrastructure proportionate to the gate it measures, and faking a freeze or shipping an empty suite to turn a row green is the violation, not the fix ("Scaffold openly; never fake done", root `CLAUDE.md`). What has changed is that the gap is now **machine-visible rather than asserted** — and that the moment someone does freeze a text, the command fails until its suite exists. The rule finally has something enforcing it instead of a sentence describing it.

**Reasoning for lifting (2)-trademark and (4)-timing — one reason, and that reason is something that already happened:**

Both conditions were written when **the repo did not exist**. They protected a private-first world. That world has ended: `ecoma-io/ecoma` **is public**, carrying the name Ecoma throughout the README, CONTRIBUTING, package names and URLs. The risk they guarded — the name leaking before registration, the intent leaking before a product — **has already been spent** by opening the repo, deliberately and for good reasons. Keeping them is guarding a door that is already open.

Three further arguments, heaviest first:

1. **This policy already contains its own counterargument.** It lets **the rubric go before everything**, on the reasoning that a self-adversarial method is content no competitor can narrate. But **a methodology published without the artefact it operates on is an unverifiable boast**. The ceiling is that boast's evidence. Letting the method go first while holding back the evidence publishes exactly the weaker half.
2. **The moat is not in the ceiling.** What distinguishes ecoma is **governance and provenance**, not the primitives. Copy five primitives and five invariants and you have a blueprint; you have no calibration data, no provenance, and no tenant's trust. Publishing a design whose value lies in execution is cheap publishing.
3. **Keeping the documents outside the repo is a cost that is actively bleeding.** One working period alone produced **four drift incidents** (version drift across 12 files · three lines of phantom debt · four obligations of hidden debt · a handoff plan out of step with reality) — all because the documents lived beyond the gates' reach. Every round of delay is another crop of drift.

**Consequence**: the ceiling is **no longer blocked by timing**. Exactly two things remain, both editorial and both doable now: **the tone pass** and **the per-file status banner**.

## Review instrument

Every review pass (incremental / cluster / full) obeys two documents at once. The **[review-constitution](../method/review-constitution.md)** owns the form — the judgment laws, the procedure a run follows, and the method that generates a rubric for an object that has none. The **[review-rubric](../method/review-rubric.md)** owns this corpus's content — groups **A–P** (P includes **P5 Change lifecycle** and **P3b**, the reverse-direction interference rule), the rules it still holds itself (**R2, R3, R5, R7, R10–R12**), **L7** (document identity), the eight-phase pipeline, and the **adversarial patch pass** at phase 7. **A full-pass litmus is 172 questions**, recomputed under the constitution's counting-last step: **20** (3 North Stars) + **127** (the L5 sets of **27 specs** — Tenant 10, Release & Compat 9, Clickstream Ingest 7, Human Surface 7, Quota & Scheduling 7, Runtime Sandbox 7, Vault 7, Working Data 6, Calibration 5, Event Log 5, Memory 5, Test harness 5, Handoff 4, Task 4, the rest 3 each) + **25** (Website 7 + Eng 9 + **Deploy 9**). **Never copy a number by hand** — every litmus figure must be re-countable by script from the corpus itself. A freeze pass must be runnable by a fresh context given only the documents plus that file.

## Discipline after a freeze

- **Documents carry no version number** (owner's decision, rule L7): the identity of a change is its **commit**. A per-file version number would be a second source of truth about a document's identity, needing manual synchronisation in two places — and it had already drifted across **12 files**. Git history has one home and is verifiable.
- A new concept must answer: is it the entity, the policy, or the template of which mechanism?
- A new contradiction is resolved in this order: **invariant > canonical principle > domain principle > template**.
- A roadmap slice may only narrow value or policy — it may never violate a ceiling mechanism. The roadmap lives at `[roadmap](../method/roadmap.md)`; **G1 (no phase language) applies to the ceiling only** — the roadmap is allowed to say phase/v1.
