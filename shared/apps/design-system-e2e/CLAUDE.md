# design-system-e2e (`shared/apps/design-system-e2e`)

Directory-scoped mechanics only — principles live in the root `CLAUDE.md`, cross-product rules in `shared/CLAUDE.md`. Nx project name `design-system-e2e` (tags `type:e2e`, `scope:shared`); its own project because e2e tests are never co-located (root `CLAUDE.md` test taxonomy). Drives the **built** Storybook of the `design-system` app (which renders `core-ui`'s stories) via `dev-cli run-e2e`; `implicitDependencies: ["design-system", "core-ui", "dev-cli"]` — `core-ui` because the token probes read its `tokens.css` off disk (no import edge sees a stylesheet), and `dev-cli` because it _is_ this suite's runner, and a suite that no longer runs after a change to its own runner would be reported as green by `nx affected`.

- **This project owns three blocking gates, one file each, and they share their preview mechanics.** `storybook-a11y.e2e.test.ts` (axe over every story), `design-tokens.e2e.test.ts` (the token contract), `palette-conformance.e2e.test.ts` (every story paints only palette colours). `storybook-preview.ts` and `token-probe.ts` are NOT test files — their names match no `testMatch` pattern, so collection ignores them. Anything a second gate needs (the story derivation, the render latch, `storyUrl`, the token probes) belongs there rather than copied: two gates disagreeing about which stories exist is exactly the silent-coverage-loss failure these suites exist to prevent.
- **This suite owns the blocking a11y gate.** The `design-system` dev Storybook shows a live a11y panel, but the scan that fails a build is here — axe (`@axe-core/playwright`) over every story in `storybook-static`. Scanning the built artifact is the point: a violation the build introduces (a dropped stylesheet collapsing contrast, an asset that 404s) is invisible to any scan against source.
- **A token must be probed on a FRESH element every single time — this is the one footgun that makes a green run meaningless.** Chromium caches the computed `color` of an element whose value contains `var()`: assigning a _different_ `var()` reference to the same element does not recompute, so every token after the first reports the FIRST one's colour. It does not fail — it silently returns plausible numbers, which is how it survived a full probe run reporting every token at one luminance, every contrast pair at 1:1, and the elevation law as violated. Resetting to `""` in between and going through an indirect custom property were both tried and both still report the first colour. `paint()` in `token-probe.ts` creates one element per expression for this reason; do not "optimise" it into a loop over one element.
- **Non-resolution is detected by inheritance, not by an exception.** `color` is inherited, so `hsl(var(--deleted))` is invalid at computed-value time and falls back to the parent rather than announcing anything. `paint()` parents every probe to a holder painted `UNRESOLVED` (`rgb(1, 2, 3)`, a value no Alloy token has), which turns that silent fallback into a reading. Two consequences: any test comparing two tokens must assert neither is `UNRESOLVED` _before_ comparing them, or a deleted palette passes by making both sides equal; and `paint()` doubles as a colour _detector_, which is how the `--seam` and `--halo` tests sort a gradient's or a shadow's parts into colours and lengths without a hand-written CSS parser.
- **The token contract deliberately loads the BARE `/iframe.html`, with no story id.** The tokens are on `:root` via `global.css`, which the preview bundle imports at module scope, so nothing has to render for them to resolve (verified: the bare preview returns 200 and resolves the full palette). Loading no story is the stronger test — it pins the stylesheet as the build ships it, with no component in the way to make a green run depend on one story's markup.
- **What the token contract pins is prose that nothing else holds, and literals that restate other tokens.** `tokens.css` states the elevation rhythm (`--sunken` < `--background` < `--card`), "focus ring = Human steel", and the seam being the two forces meeting — then spells `--primary`'s channels out as literals inside `--seam`, `--halo` and `--ring` instead of referencing it. That duplication is a live Rule 14 drift risk; these tests are what make it safe, failing with the drifted values named the day a force is retuned. Also pinned: every derived `--X`/`--X-foreground` pair clears WCAG AA at the PALETTE level, which the axe sweep structurally cannot reach — axe only judges combinations some story happens to render, so a pair no story uses today ships unchecked. The tightest is `--muted`/`--muted-foreground` at 4.68:1, 0.18 above the bar.
- **The palette sweep is what finally enforces `core-ui`'s "never hardcode colors".** Until it existed, a `text-[#3b82f6]` passed the unit tier (jsdom resolves no colours) and passed axe (a hardcoded colour with good contrast is perfectly accessible), surfacing only as a surface that stopped following a retuned token. It checks `color`, `background-color`, all four `border-*-color` (only where that side actually draws) and `outline-color`; measured across every built story: zero off-palette. It deliberately does NOT check `fill`/`stroke` — both are inherited and compute on every element, so a plain `<div>` reports `fill: rgb(0, 0, 0)` while painting nothing (718 such readings), and narrowing to SVG shapes leaves only the brand artwork in `core-ui/docs/design/assets/*.svg`, which carries a fixed brand palette on purpose. A logo that re-tinted itself when `--primary` was retuned would be the bug.
- **The WCAG scope is imported, never restated.** `WCAG_TAGS` comes from `@ecoma-io/ui/a11y` (`src/lib/a11y-scope.ts`), shared with the `design-system` app's `.storybook/preview.ts`. A second copy here would let the interactive panel and the blocking gate disagree about what counts as a violation (Rule 14).
- **`lint` carries `check-e2e-story-coverage`, and it guards the blind spot in the derivation below.** Deriving the story list from `index.json` means a component with no story contributes no entry, so the sweep passes without ever having looked at it — coverage shrinks silently while the gate stays green. The command holds every component in `core-ui/src` (any directory with a `.vue` of its own name, so `primitives`, `blocks`, and any category invented later) to owning a `<Name>.stories.ts`. It refuses to report a pass when its path matches no tracked files: a gate that silently checks nothing is worse than no gate. It runs in `lint`, not `e2e`, so the answer arrives without a browser or a Storybook build.
- **The story list is derived from the artifact**, by reading the built Storybook's own `index.json` — never hand-listed. A new primitive is covered the moment its story exists; a removed one drops out on its own. `type: "docs"` entries are filtered out (MDX pages are prose, not a component render). It is read from **disk at collection time**, not fetched over HTTP: the list decides how many tests exist, and Playwright fixes the test list before `webServer` starts. That ordering is why the Storybook build is the `e2e` target's `dependsOn` rather than a step inside `webServer` — the artifact has to exist before this file is even loaded. Running Playwright directly instead of through the Nx target therefore fails loudly, naming the target to use.
- **The scan waits on Storybook's `storyRendered`, never on `#storybook-root`.** That div is static markup in `iframe.html`, so waiting for it to be attached resolves at parse time and axe can scan an empty shell — the worse half of that bug, because it reports green having looked at nothing. Measured over 60 samples: 10 scanned a childless root, and every `color-contrast` flake in the sweep coincided with one. `storyRendered` is emitted in Storybook's own `completed` phase, after render and after any play function; the test latches it from `addInitScript` because the preview can emit it before a listener could attach. `sb-show-main` is not a substitute — `prepareForStory()` sets that class _before_ rendering.
- **`contextOptions: { reducedMotion: "reduce" }` is what makes contrast deterministic, and no amount of waiting replaces it.** axe reads the _computed_ colour, so an element part-way through an entrance animation blends toward its backdrop and is reported as a violation it does not have. Awaiting `document.getAnimations()` closes only the CSS half: a GSAP tween is rAF over inline styles and never appears there, which is why `demos-design--gsap-accent` still failed 3 of 3 behind a correct render wait. Reduced motion removes the window instead of racing it — `core-ui`'s `global.css` collapses every CSS animation to 0.01ms under it, and `GsapAccentDemo` skips its timeline to the end state. Measured: with it, 4 of 4 full sweeps clean and axe checks exactly 3319 nodes every run; without it, 3 sweeps of 4 red and 3237–3242 nodes — it raises coverage as well as stabilising it.
- **axe scans the whole document, deliberately not `#storybook-root`.** Every overlay primitive (DropdownMenu, Dialog, Tooltip, Toast) portals its content to `document.body`, outside that root — scoping the scan to the root skips exactly the surfaces whose a11y is hardest to get right while the story that opened them still counts as scanned. Bare mode renders the story alone, so there is no chrome the wider scope drags in.
- **`UPSTREAM_FOCUS_PATTERNS` is the one allowance, and it is keyed by story _and_ rule.** Two reka-ui 2.10.1 patterns trip `aria-hidden-focus` because axe reads a single DOM snapshot and cannot see a focus trap: Toast's `VisuallyHidden feature="focusable"` sentinels (`dist/Toast/FocusProxy.js`) and DropdownMenu's `hideOthers()` (`dist/shared/useHideOthers.js`). Never widen this into a `disableRules` — another story hitting the same rule must still fail. It is guarded from rotting at both ends, and both guards must survive edits to the list: the story's own scan asserts the allowed rule was actually reported, so an entry upstream fixes turns the gate red asking to be deleted; and a separate test asserts every entry still names a live story, which is the case no per-story scan would ever reach (a renamed story silently retires its own allowance).
- **`alloyBare=1` on every story URL is load-bearing.** The `design-system` app's `.storybook/PreviewSurface.vue` wraps each story in a viewport-picker surface that nests a _second_ `iframe.html` of the same story. Without the flag axe reports every violation twice and attributes half of them to chrome this suite does not own.
- `e2e` runs through `dev-cli run-e2e` (resolves the Playwright CLI, runs under xvfb on Linux) — never call `playwright` directly, so the browser-provisioning shim stays in one place (the cloud sandbox pre-installs a Chromium whose build differs from Playwright's expected one; `run-e2e` and `playwright.config.ts` carry the guarded `executablePath`).
- The Playwright `webServer` only **serves** — it runs `vite preview` **directly**, not through an Nx target: an nx-wrapped child gets its own session, so Playwright's process-group teardown can't reap it and the preview server leaks past the run. Do not "tidy" this back to an nx target. The build is not in this command at all; it is the `e2e` target's `dependsOn` (see the derivation bullet above). **The `exec` prefix on that command is load-bearing for the same reason as the Nx point:** Playwright runs it through `/bin/sh -c` and kills the shell on teardown, so without `exec` the `node` child survives holding port 4174 and the _next_ run dies with "already used" while the orphan ages out a minute later. Never "fix" that by setting `reuseExistingServer` — that would let a run scan a stale artifact.
- **Every story is its own test, and that is what makes the gate parallel.** An a11y regression usually lands across several stories at once, and stopping at the first hides the shape of it — Playwright runs every test and reports every failure, so the whole shape still arrives, now with each violation attached to the story that has it. The lever is `fullyParallel`, not the worker count: Playwright's default keeps tests from one file in a single worker, so raising `workers` alone measured flat at 1/4/8/16. Worker count is left unset for Playwright to size to the machine. Measured over 99 stories: 47.7s for the old single-worker sweep, 27.4s here.
- **A worker-scoped shared page was measured, and rejected — do not reintroduce it.** Reusing one page across the stories a worker handles keeps a warm HTTP cache and is genuinely faster (541ms per story against 935ms; 18.5s against 27.4s end to end). It is also fragile in a way the numbers hide: a hand-made `browser.newContext()` is a lifecycle Playwright does not own, so nothing recreates it, and one transient browser death failed every remaining story on that worker — 16 at once, all reporting `Target page, context or browser has been closed`. Measured on one machine: shared page red in 2 of 3 runs at load 23, the plain `page` fixture green in 3 of 3 at load 32. The ~30% is the price of Playwright owning the browser lifecycle, and a gate that fails when the machine is busy is not a gate.
- **`reducedMotion` reaching the page is itself pinned by a test.** Losing it does not fail loudly — it comes back as contrast violations on whichever stories were caught mid-animation, on whichever run. The default `page` fixture inherits it from `use.contextOptions`; a fixture that built its own context would not, which is the trap the rejected design above sat on.
