# design-system (`shared/apps/design-system`)

Directory-scoped mechanics only — principles live in the root `CLAUDE.md`, cross-product rules in `shared/CLAUDE.md`. Nx project name `design-system` (tags `type:app`, `scope:shared`); not importable — it is an app shell, not a library. It owns the Storybook **host**: the config, Tailwind wiring, and preview chrome that render `core-ui`'s stories and design docs. All content lives in `core-ui` (stories, MDX, tokens, `tailwind.preset.js`); this app contributes zero components. `implicitDependencies: ["core-ui"]` because the story globs reach into `core-ui`'s tree — glob edges are invisible to the import graph, and without the explicit edge `nx affected` would skip rebuilding this app when a story changes.

- **Why this is an app and not part of `core-ui`:** libs are buildless by workspace practice, and this Storybook has a build artifact with a lifecycle of its own — `storybook-static` is what `design-system-e2e` gates and what the future ecoma.io website will publish. The app boundary is the seam that keeps `core-ui` a pure buildless lib.
- **The recorded website edge (design intent, not a live target):** ecoma.io is planned as one site — marketing, developer docs, and the design system as one section — with per-PR preview deploys on their own subdomains. When a website app lands, its deploy target declares `dependsOn`/`implicitDependencies` on `design-system` and mounts `storybook-static` under `/design-system/`; nothing renders that seam today (root `CLAUDE.md`: reserve the seam, never ship a dead surface). Preview deploys for fork PRs must use the two-workflow pattern (build without secrets via `pull_request`, deploy via `workflow_run` that never checks out PR code) and must not live on the production cookie domain.
- **Targets are `build`, `serve`, `lint` — deliberately no `typecheck` or `test`.** The `.storybook/*.ts` files are config executed by Storybook's own toolchain; they were never typechecked when they lived under `core-ui` either, and every component they render is typechecked and tested in `core-ui`. `build` emits `{projectRoot}/storybook-static` (the e2e suite reads its `index.json` from disk at collection time — see `design-system-e2e`'s `CLAUDE.md`); `serve` is the dev Storybook on port 6008, a runtime target — start it only when a task needs runtime evidence.
- **Vite aliases are derived from `tsconfig.base.json` `paths` in `main.ts`'s `viteFinal`, never restated** (Rule 14). They exist because this app is a different Nx project from `core-ui`: `preview.ts` / `PreviewSurface.vue` must import through the public `@ecoma-io/ui` aliases (relative imports across projects are banned by `@nx/enforce-module-boundaries`), and Vite knows nothing about tsconfig `paths`. Non-wildcard keys become exact-match regexes so `@ecoma-io/ui` never shadows its own subpath entries.
- **`tailwind.config.js` is the one file that CANNOT use the alias**, because Tailwind's `@config` loads it through jiti, which resolves neither tsconfig paths nor the Vite aliases above — it imports `core-ui`'s `tailwind.preset.js` relatively, under a scoped `eslint-disable-next-line @nx/enforce-module-boundaries`. Don't "fix" that import to the alias; it breaks the CSS build silently (utilities stop generating).
- **`postcss.config.js` (`@tailwindcss/postcss`) must stay at this app's root.** Tailwind v4 generates no utilities without it; postcss-load-config walks up from the Vite root (`.storybook/`) and finds it here. Only the shim lives here — the theme source stays in `core-ui`'s `tailwind.preset.js` (one source of truth).
- **`PreviewSurface.vue` wraps every story in a viewport-picker surface that nests a second `iframe.html` of the same story**; `alloyBare=1` renders the story alone. The e2e suite depends on that flag — without it axe reports every violation twice (see `design-system-e2e`'s `CLAUDE.md`).
- `main.ts`'s `viteFinal` carries two more landmines, documented inline: `server.fs.allow` must widen to the repo root (no `pnpm-workspace.yaml` means Vite's root auto-detection stops at this project and would deny every root-hoisted dependency), and `@vitejs/plugin-vue` must be **prepended** (the framework ships none of its own, and vue-docgen's transform assumes the SFC is already compiled).
- Story-sidebar shape is content-owned: every `core-ui` story carries an explicit `title:` and every MDX binds via `of=`/`title=`, so story IDs are independent of this app's glob prefixes — moving the host (as this app's creation proved) changes zero IDs.
