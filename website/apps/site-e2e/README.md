# site-e2e

The blocking Playwright gate over the built ecoma.io website shell
(`site`). It drives the `dist/` artifact produced by `nuxt generate` and
pins the SEO contract a future content build must not regress: per-locale
`html lang`, hreflang alternates with `x-default`, canonical links naming
the production origin, the language switcher, and `robots.txt`.

<!-- readme:why -->

## Why it exists

The shell's SEO surface is generated by `@nuxtjs/i18n` from a config file —
a hand-rolled `<link rel="alternate">` or a missing canonical in a later
content build would pass every lint. Reading the built HTML instead pins
what actually ships, the same reason the other e2e suites scan built
artifacts rather than source.

<!-- readme:consumers -->

## Who consumes it

Every change touching `site` — `nx affected` runs this suite whenever the
app's build changes, and the `e2e` target depends on that build, so the
artifact under test is never stale.

<!-- readme:ecosystem -->

## Where it sits

`website/apps/site-e2e`, tagged `type:e2e`, `scope:website`. It runs through
`dev-cli run-e2e` (xvfb on Linux, browser shim in one place) and serves the
built `dist/` via `vite preview` on port 4176. Mechanics in
[`./CLAUDE.md`](./CLAUDE.md).

<!-- readme:boundary -->

## What it does not cover

The preview-`noindex` half of the robots contract: proving
`NUXT_PUBLIC_PREVIEW=true` adds the robots meta needs a second build, so it
is checked by hand and recorded in `site/CLAUDE.md` — the suite never
claims a coverage it does not have.

## Status

One suite file (`shell.e2e.test.ts`) covering the shell's SEO contract —
mechanics in [`./CLAUDE.md`](./CLAUDE.md), suite in [`./src`](./src).
