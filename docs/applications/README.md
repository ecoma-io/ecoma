# Applications

> **Phạm vi:** view **Applications** — các **executable software component** của Ecoma và composition của chúng: UI/BFF, API service, control plane, data plane, background worker và maintenance job.
>
> Application **không** đồng nghĩa bounded context, Nx project, deploy unit hay Pulumi deployment project. Một Application có thể chứa nhiều deploy unit và host nhiều bounded context; một bounded context có thể được hiện thực qua nhiều Application.
>
> Business model, rule và invariant → [`domains/`](../domains/README.md). System topology, data ownership cấp hệ thống và ràng buộc toàn hệ thống → [`architecture/`](../architecture/README.md). User capability → [`features/`](../features/README.md).

## 1. Cách đọc

- Danh sách dưới đây chỉ gồm component **có tài liệu**. Một deploy unit chưa có tài liệu không được liệt kê.
- Cột **Bounded context** ghi context mà component **host, compose hoặc tiêu thụ qua contract** — không phải quyền sở hữu domain. Application host implementation của một context không làm nó sở hữu context đó.
- Danh sách này **không** phải bản sao của bảng deploy unit trong [`architecture/01-architecture.md`](../architecture/01-architecture.md) §2: Architecture sở hữu topology và ranh giới deploy; tài liệu này sở hữu thiết kế và vận hành của từng component.
- Background job nằm **phẳng** cạnh API/BFF. Không có `applications/jobs/`.
- ADR không nằm trong `applications/<component>/adr/`; ADR thuộc `domains/<context>/adr/` kể cả khi quyết định có phạm vi application.

## 3. Cấu trúc một Application

`applications/<component>/` gồm:

- `README.md` — purpose, component type, responsibility và boundary, domain context tham gia, tài liệu bên trong.
- `01-architecture.md` — composition, runtime/process boundary, application flow và orchestration, API/protocol surface, integration và adapter, persistence implementation, runtime security, execution/failure model, dependency tới domain context, application-level invariant. Business semantics do Domain Model sở hữu được thay bằng pointer.
- `02-requirements.md` — chỉ application-specific requirement: protocol compatibility, interface, runtime constraint, performance/scalability, technical security, availability/recovery, technical non-goal.
- `03-operations.md` — deployment, configuration/secret, database migration operation, monitoring/alert, failure handling, recovery, runbook. System-wide operational policy vẫn thuộc [`architecture/03-operations.md`](../architecture/03-operations.md).

Tài liệu bổ sung chỉ được tạo khi có subject, ownership và lifecycle riêng — ví dụ `UPSTREAM_MAPPING.md` của `pact-broker`. Không tạo `database.md`, `api.md`, `testing.md` chỉ vì component có nội dung tương ứng.

## 4. Ba khái niệm không được nhầm

| Khái niệm                         | Thuộc view                                    | Ví dụ                                                     |
| --------------------------------- | --------------------------------------------- | --------------------------------------------------------- |
| **Domain service**                | Domains                                       | Quy tắc xác định một payout request có đủ điều kiện duyệt |
| **Application service/use case**  | Applications                                  | Use case orchestration gọi domain operation rồi ghi state |
| **Deployable service/worker/job** | Applications, mô tả topology bởi Architecture | Một Worker hoặc Queue consumer cụ thể                     |

Không dùng từ "service" mà không xác định đang nói tới loại nào.
