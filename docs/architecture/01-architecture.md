## 1. System Topology

**Mọi deploy unit chạy trên Cloudflare Workers; chỉ tầng lưu trữ nằm ngoài Workers.** Ở đây _deploy unit_ luôn nghĩa là
**một Worker/runtime unit** — không phải Pulumi project trong `deploys/` (provisioning, không phải một deploy unit).

```text
Client
  │
  ▼
Cloudflare ── DNS · TLS · WAF · Rate Limiting · Turnstile
  │
  ├── Public hostname (§7) ──► apps · account · auth · backoffice · payment · llm-api · cache   (ecoma.io — production, không qua Router)
  ├── Non-production hostname (§7) ──► Router → staging / preview Worker                  (ecoma.io.vn)
  ├── Internal — không hostname công khai; Worker không route vẫn có *.workers.dev mặc định (§6) ──► push/mail control + job workers · janitor
  │
  ▼
Workers (deploy unit độc lập · Service Binding nội bộ)
  │
  ├── PostgreSQL   Worker → Hyperdrive → Workers VPC Service → Cloudflare Tunnel → private network
  │                account · auth · payment · llm-api · backoffice   (mỗi service một database · query cache OFF)
  ├── D1           Worker → D1 binding            · push · mail bounded context
  ├── KV / Queue   Worker → binding               · non-authoritative
  ├── Queue consumer Worker ── asynchronous delivery / background work
  ├── External provider ── LLM · email · web push · payment
  └── R2/B2 ── backup copy · build artifact       · không business authority
```

### 1.1 Ba đường truy cập lưu trữ

| Nhóm           | Đường duy nhất từ application code                                                             |
| -------------- | ---------------------------------------------------------------------------------------------- |
| **PostgreSQL** | `Worker → Hyperdrive → Workers VPC Service → Cloudflare Tunnel → private network → PostgreSQL` |
| **D1**         | `Worker → D1 binding → D1`                                                                     |
| **KV / Queue** | `Worker → KV/Queue binding`                                                                    |

- Hyperdrive là boundary duy nhất từ application code tới PostgreSQL; origin private chỉ reachable qua Workers VPC Service + Cloudflare Tunnel, TLS bắt buộc, query cache OFF trên mọi đường correctness (limit và source → `04`).
- D1 không đi qua Hyperdrive, không có Tunnel, không có VPS.
- **Không có Worker nào giữ correctness state:** isolate không ổn định giữa hai request, `/tmp` memory-backed; mọi authoritative state nằm ở PostgreSQL hoặc D1, và không dựa vào `ctx.waitUntil()` cho correctness write.
- Application, database connectivity và database hosting thay đổi theo ba nhịp khác nhau; chỉ tầng hosting thay đổi theo trigger vận hành, nên nâng cấp hạ tầng không thành rewrite (tier → `03` §6).

### 2.1 Bounded context `account` và `auth`: hai context, hai deploy unit serving

`account` và `auth` là **hai bounded context riêng** (catalog → [`domains/README.md`](../domains/README.md) §2), mỗi context một deploy unit serving và một database owner:

| Deploy unit | Bounded context | Sở hữu                                                                | Không sở hữu                       |
| ----------- | --------------- | --------------------------------------------------------------------- | ---------------------------------- |
| `account`   | `account`       | Account UI, BFF, **login và consent UI**, credential, browser session | Endpoint protocol OAuth 2.0/OIDC   |
| `auth`      | `auth`          | Endpoint **protocol** OAuth 2.0/OIDC                                  | Account page, UI quản lý tài khoản |

- Ranh giới giữa hai context này là **service boundary, deployment boundary, protocol boundary và security boundary** — và vì trách nhiệm nghiệp vụ tách riêng (danh tính đăng nhập ≠ giao thức ủy quyền), nó là **context boundary**. Quyết định trước đây coi hai deploy unit là một bounded context (`identity`) đã bị đảo (A10): mỗi bên giờ có catalog riêng, `sub` riêng của mình, và data ownership riêng.
- `auth` là **API-only**: không Nuxt, không Vue, không trang login hay consent. UI nào liên quan tài khoản đều thuộc `account`.
- **Không suy ra chung database từ bất cứ điều gì.** Hai database riêng, hai owner, hai role riêng (A2, A9). Design chi tiết — ma trận ownership và login/consent contract → [`docs/domains/account/`](../domains/account/README.md) và [`docs/applications/auth/`](../domains/auth/README.md). Trách nhiệm nghiệp vụ của từng context trong catalog → [`domains/README.md`](../domains/README.md) §2.

### 2.2 Bounded context `backoffice`: một deploy unit

> **Framing target (A21 evolution):** A21 gán trách nhiệm staff/RBAC cho `backoffice`; trách nhiệm đó đã chuyển sang bounded context `staff-access` — chốt bằng [ADR-0013](../domains/staff-access/adr/0013-staff-access-ownership-transfer.md), supersede phạm vi sở hữu staff/RBAC của A21. Sau chuyển đổi, `backoffice` chỉ còn composition/UI + BFF và **không** còn là bounded context (catalog → [`docs/domains/README.md`](../domains/README.md) §2/§3; evolution → [`docs/domains/staff-access/`](../domains/staff-access/README.md) §4). Nội dung dưới đây mô tả ranh giới theo A21 trong phần chưa bị supersede.

`backoffice` là bounded context riêng (Nx tag `scope:backoffice`) gồm **một** deploy unit: Nuxt + BFF tại `office.ecoma.io`. Không có tách protocol/UI như cặp `account`/`auth`: toàn bộ UI quản trị và authorization nằm trong cùng một đơn vị triển khai.

| Deploy unit  | Sở hữu                                                                                                                              | Không sở hữu                                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `backoffice` | Staff directory, staff lifecycle, permission catalog, role, staff-role assignment, authorization audit, workflow thao tác đặc quyền | Danh tính account và credential/MFA/passkey; endpoint protocol OAuth 2.0/OIDC; dữ liệu nghiệp vụ của resource-owning backend khác |

- **Danh tính xuyên service là Account ID (`sub`)**, không phải email. Một staff member liên kết đúng một Account ID; đó là tham chiếu, không phải foreign key xuyên database (§9 invariant 7).
- **`backoffice` không phải IdP thứ hai và không phải credential store.** Authentication đi qua `auth` và `account` như mọi application khác; `backoffice` chỉ tiêu thụ kết quả đã xác thực. Không nhân bản credential, MFA/passkey hay passwordless state vào đây.
- **Enforcement chia đôi, không hợp nhất.** `backoffice` định nghĩa permission và vòng đời của chúng; **resource-owning backend enforce** permission đó trên operation và tài nguyên của chính nó, trên **mọi** protected request. Hình dạng kênh lan truyền đã chốt ở ADR-0009 (batch/event-based sync, không sync call per request); **cơ chế cụ thể** và cách bảo đảm revocation latency là quyết định chưa chốt (§10, [`open-boundaries.md`](../domains/open-boundaries.md) OB-2); backend không tự phát minh permission ngoài catalog.
- Ranh giới này là quyết định kiến trúc **A21–A24** (§8; phạm vi sở hữu staff/RBAC đã chuyển sang `staff-access` theo [ADR-0013](../domains/staff-access/adr/0013-staff-access-ownership-transfer.md)); database và schema staff/RBAC đã chốt: `db-staff-access`/`staff_access` (ADR-0013). Design chi tiết → [`docs/domains/staff-access/`](../domains/staff-access/README.md); vai trò của `backoffice` trong context map → [`context-map.md`](../domains/context-map.md) §3.

⚠️ **Danh tính xuyên service là Account ID (`sub`), không phải email.** `account` sở hữu danh tính account; `auth` sở hữu giao thức OAuth 2.0/OIDC; `staff-access` sở hữu staff, role và permission nghiệp vụ. `account` và `auth` **không** sở hữu staff membership, role hay permission của `staff-access`; `staff-access` **không** giữ credential, MFA/passkey hay passwordless state. Ranh giới đầy đủ → §2.2 và [`docs/domains/staff-access/`](../domains/staff-access/README.md).

⚠️ **`db-account` và `db-auth` chưa được provision.** Schema và migration **đã có trong repo** (`apps/account/db/migrations/` 0001–0007, `apps/auth/migrations/` 0001–0014) và được integration test phủ, nhưng không database nào tồn tại — Hyperdrive binding chưa trỏ được tới origin thật. `db-account`/`db-auth` ở đây là **target đã chốt**, không phải tài nguyên đang tồn tại. Kế hoạch provisioning và validation → [`docs/applications/account/03-operations.md`](../applications/account/03-operations.md) §3.2.

**Storage model** — quy tắc architectural, không phải platform limit (limit → `04`):

| Storage                            | Vai trò                          | Business authority |
| ---------------------------------- | -------------------------------- | ------------------ |
| PostgreSQL                         | Core relational state            | **Yes**            |
| D1                                 | Supporting service state         | **Yes**            |
| KV · Queue · Worker memory · cache | Async · ephemeral · acceleration | **No**             |
| R2/B2                              | Backup copy · build artifact     | **No**             |

- **Mỗi authoritative storage resource có đúng một business owner** (A9). Một service có thể sở hữu nhiều storage resource; storage resource không bao giờ có nhiều owner.
- **Owner là service, không phải bounded context.** Một bounded context có thể có nhiều storage owner khi nó có nhiều deploy unit; ở đây thì ngược lại, mỗi context `account`/`auth` có đúng **một** owner — `account` sở hữu `db-account`, `auth` sở hữu `db-auth` — và ranh giới giữa hai owner vừa là service boundary vừa là context boundary (§2.1).
- Chọn PostgreSQL hay D1 theo **bounded context** (transactional requirement, relational complexity, portability, operational cost, workload, recovery), **không** theo mức quan trọng của dữ liệu: criticality quyết định durability/backup/retention, không tự nó quyết định technology (A20).
- Database hosting tier ở mức khái niệm: **Tier 0** self-hosted PostgreSQL → **Tier 1** managed → **Tier 2** managed HA — chỉ mô tả PostgreSQL; D1 là managed service, không thuộc thang tier này. Trigger, sizing, backup, RPO/RTO → `03` §6.

## 5. Cross-Service Communication

```text
Service A ──► API (sync) / Event (async) / Service Binding ──► Service B
   ✗ truy cập trực tiếp database hoặc implementation nội bộ của Service B
```

- Cross-service **chỉ** qua API, event hoặc Service Binding. Không tồn tại cross-database query; cần dữ liệu do service khác sở hữu thì synchronous API, event, hoặc local projection được đồng bộ có chủ đích.
- Cùng một Cloudflare account: Worker ↔ Worker đi qua Service Binding, không qua internet. Event liên service giao bằng HTTPS có idempotency key và xác thực service-to-service.
- Event bất đối xứng đi qua **transactional outbox** nằm chung transaction với state (A8): bản ghi event không mất khi commit thành công. Cơ chế relay đã chốt cho `staff-access` tại [ADR-0016](../domains/staff-access/adr/0016-outbox-relay-mechanism.md); reconciliation (#453) chưa có ADR riêng. Context khác dùng cùng hình dạng cho tới khi có ADR riêng (§10). Queue chỉ là delivery channel, không bao giờ là source of truth; consumer phải idempotent; thứ tự là thuộc tính của consumer, không phải của kênh.
- Mọi event có tên, version, schema, idempotency key, correlation ID, chính sách compat/replay, và breaking change bị chặn ở Contracts Registry (`02` §3).

## 6. Security Boundaries

- **Secret:** production secret không bao giờ xuất hiện trong PR build hay Preview runtime; Worker runtime chỉ giữ credential mà role đó cần; secret dùng native Worker Secrets theo môi trường deploy, xoay vòng đi qua delivery gate (`02` §6).
- **Database:** không truy cập database của service khác (§5); PostgreSQL không có địa chỉ công khai — mọi đường vào đi qua Workers VPC Service + Cloudflare Tunnel; D1 chỉ qua D1 binding; private database không public.
- **External boundary:** hostname public và API công khai phải có authentication/authorization phù hợp; cookie session isolate theo từng hostname (`__Host-*`, `HttpOnly`, `Secure`, `SameSite=Lax`); authorization không dựa vào độ khó đoán của ID.
- Endpoint chỉ dùng Service Binding **không** tự động private: Worker không cấu hình `routes` vẫn có hostname công khai `*.workers.dev` mặc định, và Cloudflare **không** cấp header phân biệt cuộc gọi Service Binding với request từ Internet. Vì vậy service chỉ dùng Service Binding **MUST** (a) xác thực caller ở tầng ứng dụng, và (b) tắt `workers_dev` trước khi chạy ở production — kiểm ở deploy, không dựa vào quy ước (`02` §5).
- **Shared-origin `ecoma.io/*`:** XSS ở một app ảnh hưởng app cùng origin → strict CSP + nonce, cấm inline script, sanitize server-side; thao tác nhạy cảm cần step-up auth; `account`/`auth`/`office`/`payment` luôn là hostname riêng.
- **Protocol boundary `account` ↔ `auth`:** `auth` nằm sau hostname riêng và là API-only, nên nó là **trust boundary** chứ không phải một route nữa của `account`. `account` không tự implement endpoint protocol để tránh trở thành authorization server thứ hai; `auth` không render UI account. Cookie session isolate theo từng hostname, nên hai service không dùng chung cookie scope. Login/consent contract chọn được → [`docs/applications/auth/01-architecture.md`](../applications/auth/01-architecture.md) §4.2.
- **Observability:** không tự xây ngoài Axiom, không được là serving-path dependency; không log prompt/response body, không log sensitive payload (`03` §4).
- **Preview là runtime không tin cậy** và không ghi được storage production — enforced bằng binding, không bằng quy ước (`02` §5).

## 7. Hostname / Routing

| Hostname           | Vai trò                                                           |
| ------------------ | ----------------------------------------------------------------- |
| `ecoma.io`         | **Production public domain** — web production                     |
| `ecoma.io.vn`      | **Non-production domain** — staging + preview                     |
| `account.ecoma.io` | Account UI + BFF, gồm login và consent UI                         |
| `auth.ecoma.io`    | `auth` — API-only; endpoint protocol OAuth 2.0/OIDC khi implement |
| `office.ecoma.io`  | Backoffice                                                        |
| `payment.ecoma.io` | Payment, payment webhook                                          |
| `api.ecoma.io/llm` | Public API của `llm-api` — base path `/llm` là public contract    |
| `cache.ecoma.io`   | Data plane của `cache`                                            |

**Ranh giới routing (A13):**

```text
Production:    Client → ecoma.io → Cloudflare → production Worker
Non-production: Client → ecoma.io.vn → Non-production Router → staging / preview Worker
```

- Production **không đi qua Router**; không có global router hay routing abstraction trên production request path. Router chỉ phục vụ non-production — mục đích của `ecoma.io.vn` là để staging/preview dùng routing đơn giản mà không tạo thêm latency hay operational dependency cho production.
- Implementation của Router thuộc delivery (`02` §12); `01` chỉ ghi architecture boundary và invariant.
- **Locale (production, A13):** public URL là `/<locale>/<mount>/<path>`, locale là segment đầu tiên của mọi URL, English cũng mang prefix `/en`; `/` chỉ là locale-resolution entry point, không serve content; không có domain thị trường. Locale strategy của production giữ nguyên, không phụ thuộc vào sự tách domain non-production.
- `mount` ≠ tên app; app không phục vụ SEO không vào public route table. Production match `mount` thẳng trên path (không qua Router, không strip prefix); các hostname riêng không nằm trong route table public web.
- Mỗi resource có đúng hai URL public (`/en/...` và `/vi/...`), self-canonical, `hreflang` hai chiều `en` ↔ `vi-VN`; đổi locale chỉ khi người dùng chủ động chọn (302), không tự đổi theo IP/`Accept-Language`/cookie.
- Staging và Preview phục vụ dưới `ecoma.io.vn` (non-production); staging worker dùng prefix `stg-*`; mechanics deployment → `02` §5.

| 33  | **Authorization là deny-by-default và được enforce ở resource-owning backend trên mọi protected request**, gồm cả object-level check; UI visibility không phải authorization. Không có đường authorization chỉ ở client                                                                                                                                                                                                                                                                                                                 | Contract test + review                                                                                                                                                                             |
| 34  | **`account` và `auth` không được ghi dữ liệu staff/role/permission của `staff-access`**, dù chung PostgreSQL instance. Chỉ `staff-access` ghi authorization state của chính nó                                                                                                                                                                                                                                                                                                                                                          | Grant mức database (role riêng, `REVOKE` chéo) + review migration                                                                                                                                  |
| 35  | **Mọi thao tác thay đổi quyền để lại authorization audit** — actor, target, action, thời điểm, kết quả, lý do, request/correlation ID — và audit **không** chứa access token hay auth secret                                                                                                                                                                                                                                                                                                                                            | Test: gọi thao tác rồi assert bản ghi; grep audit không thấy token                                                                                                                                 |
| 36  | **Không có bypass không ghi tài liệu** (kể cả role hay cờ `isAdmin` cấp quyền vô hạn). Bootstrap quản trị viên đầu tiên và đường phục hồi khẩn cấp phải là đường được định nghĩa và có audit                                                                                                                                                                                                                                                                                                                                            | Review + contract test trên đường bootstrap                                                                                                                                                        |

> **Ghi chú:** đây là system invariants — cái phải luôn đúng. Cách delivery/operations/code architecture enforce từng invariant nằm ở `02`, `03`, `05`.
