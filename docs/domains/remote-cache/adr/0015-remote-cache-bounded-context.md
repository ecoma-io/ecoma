# ADR-0015 — Xác lập bounded context `remote-cache`: từ disposable build state sang multi-tenant SaaS; storage `db-remote-cache`, schema `remote_cache`

> 📌 Thư mục này là bounded context **Remote Cache** (xem [`../README.md`](../README.md)): ADR này thi hành việc chuyển đã hẹn ở A18 — từ disposable build state sang bounded context multi-tenant.

> **Trạng thái:** Accepted (Superseded (in part) by [ADR-0017](./0017-lifecycle-enforcement.md) — câu "data plane không bao giờ đọc database trong hot path": data plane re-check lifecycle state từ `db-remote-cache` mỗi request) · **Ngày:** 2026-10-31 · **Quyết định từ:** [`architecture/01-architecture.md`](../../../architecture/01-architecture.md) §8 A18 · **Issue:** #442 (umbrella #440)

## Bối cảnh

A18 ([`architecture/01-architecture.md`](../../../architecture/01-architecture.md) §8) hiện gán hai vai cho `cache`: hiện tại là **Edge deploy unit độc lập với tư cách disposable build state** (Nx cache artifact, non-authoritative), và **target** là multi-tenant SaaS bounded context `remote-cache` sở hữu tenant/project/membership/API key/quota/retention/usage/audit. A18 tự nó yêu cầu "một decision mới cần ADR khi chuyển từ disposable infra sang SaaS bounded context", và [`domains/README.md`](../../README.md) §4 rule 6 chỉ cho phép việc này qua ADR. Spec kỹ thuật đầy đủ của service đã có sẵn tại [`applications/remote-cache/`](../../../applications/remote-cache/README.md) (control plane / data plane tách, membership + API key độc lập vòng đời, quota semantics, Nx protocol adapter MVP, namespace không vào public URL) — nhưng chưa có quyết định nào chốt **ownership chạy ở tầng bounded context và database**: tên database/schema, engine, và ranh giới tenant với `pact-broker`.

Câu hỏi ADR này phải trả lời: `remote-cache` có phải bounded context riêng không, storage của nó tên gì và nằm ở đâu, tenant của nó quan hệ thế nào với tenant của `pact-broker`, và ranh giới với entitlement Staff Access đặt ra sao — để migration control plane (P4.1) có tên chốt trước khi viết DDL, đúng tiền lệ P1.1/ADR-0013.

## Quyết định

- **Xác lập bounded context `remote-cache`** trong catalog [`domains/README.md`](../../README.md) §2. Trách nhiệm sở hữu: tenant, project, membership, API key, quota, retention, usage metering, audit. Quota/retention/usage/audit được kiến trúc hoá ngay từ đây; thiếu runtime không đổi ranh giới. Ranh giới control plane / data plane và mọi bất biến serving giữ nguyên tại [`applications/remote-cache/01-architecture.md`](../../../applications/remote-cache/01-architecture.md) — ADR này không nhân bản chúng.
- **Database: `db-remote-cache`, PostgreSQL, schema `remote_cache`.** Rationale giữ nguyên pattern ADR-0001/ADR-0013: engine theo quy tắc bounded context (A20 — tenant/project/membership/API key là authoritative relational state với constraint và grant mức database), một database một owner (A9), nằm cùng PostgreSQL instance tier khởi đầu như `db-account`/`db-auth` (A2, A3). Tên schema mirror tên database để ranh giới grant đọc được ngay từ tên.
- **Mô hình role ba tầng** giữ pattern của ADR-0001/ADR-0013: `ecoma_owner` / `ecoma_remote_cache_migrator` / `ecoma_remote_cache_runtime` — tham chiếu pattern, không dùng chung credential với service nào; chặn chéo `REVOKE CONNECT` (kể cả rút khỏi `PUBLIC`) và Hyperdrive riêng với query cache OFF (A5, invariant 14). Quota authority và settlement authority của context này (từ P4.3) nằm ở PostgreSQL `db-remote-cache` theo đúng hình A7.
- **Ranh giới tenant: tenant của `remote-cache` ≠ tenant của `pact-broker`.** Hai context mỗi bên sở hữu tenant/membership/role của riêng mình; không dùng chung bảng, không suy ra membership từ bên kia, không FK chéo database. Glossary [`domains/glossary.md`](../../glossary.md) là nguồn ngôn ngữ; `sub` là tham chiếu opaque, không FK (A21 pattern). Điểm khác biệt với `pact-broker`: data plane của `remote-cache` không bao giờ đọc database trong hot path (cached configuration) **[bị thu hẹp bởi [ADR-0017](./0017-lifecycle-enforcement.md): data plane re-check lifecycle state từ `db-remote-cache` mỗi request]** — tenant state chỉ được control plane ghi và data plane tiêu thụ qua cache có TTL **[cũng bị thu hẹp: không có cache trạng thái tenant]** với enforcement fail-closed (`applications/remote-cache/01-architecture.md` §2.1); cơ chế lan truyền cụ thể được chốt riêng tại [ADR-0017](./0017-lifecycle-enforcement.md).
- **Ranh giới Staff Access: entitlement integration deferred — MVP dùng API key riêng của service.** API key của `remote-cache` là machine credential của chính context này (hash-only, show-once, revoke = set `revoked_at`, không `last_used_at` — observability không vào serving path), độc lập vòng đời với membership. Việc defer **không vi phạm ADR-0009**: không có sync-call nào tới Staff Access trong request path, và khi entitlement được tích hợp sau MVP thì hình thức duy nhất được phép là entitlement event truyền product availability (ADR-0002/ADR-0009, [`open-boundaries.md`](../../open-boundaries.md) OB-2) — không phải authorization-result contract. Cho tới lúc đó, authorization bên trong `remote-cache` resolve từ principal (API key) và dữ liệu của chính nó — catalog govern/backend enforce giữ nguyên hình dạng.
- **Không đổi:**
  - A18 giữ nguyên trong bảng §8 của hệ thống với con trỏ trỏ về ADR này; các invariant serving của `cache` (invariant 6, 14, 22) giữ nguyên.
  - Spec service tại [`applications/remote-cache/`](../../../applications/remote-cache/README.md): 01-architecture vẫn là canonical của thiết kế deploy unit, 02-requirements của FR/NFR, 03-operations của runbook — ADR này chỉ chuyển trục ownership.
  - Ranh giới ngôn ngữ protocol: Nx adapter là adapter MVP; protocol khác là adapter riêng — không thuộc quyết định này.
- **Vẫn mở (không chốt ở đây):** quota-exceeded write behavior chi tiết ngoài semantics non-fatal đã pin khi hiện thực. Cơ chế lifecycle enforcement đã chốt riêng tại [ADR-0017](./0017-lifecycle-enforcement.md).

## Hệ quả

- Mọi tham chiếu target-framing tới storage và ownership của remote-cache dùng `db-remote-cache`/`remote_cache` và con trỏ về ADR này thay vì nhân bản quyết định.
- Catalog [`domains/README.md`](../../README.md) §2 thêm entry `remote-cache`; §3 chuyển dòng `cache` khỏi danh sách "không bao giờ là bounded context" theo đúng trigger §4 rule 6; context map §3 thêm quan hệ có tài liệu hậu thuẫn.
- Provisioning `db-remote-cache` đi theo pattern bốn bước của ADR-0001 (infrastructure → expand → binding → compatible rollout) khi deploy unit được dựng (P4.1); trước khi provision thật, migration và role vẫn chốt tên ngay từ PR này.
- **Lên P4.2 (data plane):** data plane chỉ đọc cached configuration do control plane đẩy; namespace và storage scope derive từ project, không từ input client; mọi read/write qua credential project-scoped fail-closed khi tenant/project không `active` — schema control plane của PR này là hợp đồng mà cached configuration sẽ đọc từ đó. **Cập nhật cross-reference:** phần "chỉ đọc cached configuration" của bullet này bị thu hẹp bởi [ADR-0017](./0017-lifecycle-enforcement.md) — data plane re-check lifecycle state từ `db-remote-cache` mỗi request; phần còn lại của bullet vẫn hiệu lực.
- **Lên P4.3 (quota/retention/usage/audit):** bảng quota/usage/audit thuộc `db-remote-cache`, attribution theo project; semantics chống double-count và hành vi vượt quota đã được pin theo yêu cầu R14 (`429` non-fatal); audit administrative mutation append-only theo pattern `staff-access.authorization_audit`.
- **Lên P4.4 (security):** API key scope enforcement (read/write per project), cross-tenant isolation test, và authn cho administrative surface của control plane là phần còn thiếu của skeleton P4.1 — skeleton không tự coi là đã harden.
- Ngân sách vận hành: một database, một bộ ba role, một Hyperdrive config — như ADR-0001 đã tính.
